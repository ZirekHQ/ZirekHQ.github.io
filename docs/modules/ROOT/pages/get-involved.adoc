= Get involved

Zirek builds screen-reader support and local neural text-to-speech for languages large vendors don't get around to. Kurmanji is where it started, but every language is welcome, Kurdish or not. Most of the work needs native speakers, not programmers.

xref:contribute.adoc[Contribute] is the short version of this page, in Kurmanji and English.

'''

== How the project fits together

The add-ons run on the dengjen speech engine, which runs the voice models. Every project is listed under https://zirekhq.github.io/#projects[Projects] on the home page, with links to its releases, source and issues, and to its docs where it has them. xref:architecture.adoc[Architecture] shows how the pieces connect.

Kurmanji phoneme support goes upstream to https://github.com/espeak-ng/espeak-ng[espeak-ng], so every project that uses it benefits.

'''

== Translate

The NVDA add-ons are translated in the NVDA community's Crowdin project, the one every NVDA add-on uses. You need to read English, the source language, and write the language you translate into. No coding is involved.

. Create a https://crowdin.com/[Crowdin] account.
. Subscribe to the NVDA Translations mailing list; see <<mailing-lists,Join the mailing lists>>. Translation questions and announcements go there.
. Ask for access to the `nvda` and `nvdaAddon` translation teams.
. Join the NVDA Add-ons Crowdin project.
. Choose your language, whichever it is. If it is not listed, ask for it on the mailing list.
. Translate the interface strings and the documentation.

New to Crowdin? Its guide for translators is at https://support.crowdin.com/for-translators/[Crowdin for translators], and https://support.crowdin.com/online-editor/[Online Editor] explains how to translate strings in the browser.

NVDA maintains the full procedure in https://github.com/nvaccess/AddonTemplate/blob/master/docs/l10n/addonTranslators.md[addonTranslators.md]. Follow it if a step above has changed.

For a string that has no context or reads wrongly, open an issue on the https://github.com/ZirekHQ/dengjen-nvda/issues[dengjen-nvda repository] with the exact text and what it should say.

'''

== Record your voice

Text-to-speech models for any language need voice recordings from native speakers. The voices are used by blind people with NVDA, often at two to three times normal speed, so every sound has to stay clear. Consistency matters more than expressiveness.

Anyone who speaks the language natively can volunteer. The full guide, with the recording terms, the recording script, equipment, reading style and how to hand in recordings, is xref:voice-models::record-your-voice.adoc[Record your voice] in the voice-models docs. Start there, then open an issue on the https://github.com/ZirekHQ/voice-models/issues[voice-models repository] saying which language you speak.

'''

== Test

Windows testers are needed for dengjen-nvda, especially against current NVDA releases. Install the latest release, use it with your own NVDA setup, and report problems in the https://github.com/ZirekHQ/dengjen-nvda/issues[dengjen-nvda issues]. Include your NVDA and Windows versions.

'''

== Write code

Each repository owns its code, build instructions and issues. Start from the repository's README and its issue list.

* *dengjen and dengjen-tashkeel.* Rust core with Python, Java and other bindings. Fixes and binding work are welcome in both. Send Piper issues and pull requests to dengjen; dengjen-piper-rs is archived and takes none.
* *dengjen-nvda and nvda-addon-testkit.* Python, for NVDA add-on and test work.

'''

== Maintain

Every add-on and engine here has one maintainer, which is one too few. If you want to co-maintain a repository, open an issue there or contact the maintainer through the https://github.com/ZirekHQ[organization page].

'''

== Ground rules

Open an issue on the relevant repository before large changes. See the organization's https://github.com/ZirekHQ/.github/blob/main/CONTRIBUTING.md[CONTRIBUTING.md] for commit and pull-request conventions. You do not need to write code to help.
